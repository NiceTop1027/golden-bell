## 1. 개요

### 1.1 목적
- 덕영고등학교가 주최하는 공식 골든벨 대회를 웹으로 진행
- 선생님들이 미리 낸 문제로 학생 여러 명이 동시에 참여하는 서바이벌 퀴즈
- 화이트보드 확인과 손 채점 대신 자동 채점과 실시간 집계를 써서 진행 시간을 줄이고 판정 시비를 없앰

### 1.2 운영 방식 요약
- **선생님:** 웹에서 문제 출제 (OX, 객관식, 단답 등 유형 혼합)
- **관리자:** 문제 검수 → 출제 순서 편성
- **대회 당일:** 정해진 순서대로 한 문제씩 공개 → 참가 학생 전원이 각자 기기로 동시에 제출 → 타이머 종료 → 정답 공개 → 오답·미제출자 탈락
- **우승:** 마지막까지 남은 학생 (골든벨)

### 1.3 범위

| 포함 | 제외 |
|---|---|
| 선생님 출제, 관리자 검수, 순서 편성 | 학생 회원가입·로그인 |
| 실시간 대회 진행 (진행자·무대·학생 화면) | 모바일 앱 (웹으로만 제공) |
| 자동 채점, 타이머, 패자부활 | 채팅, 댓글 |
| 결과·통계·CSV 내보내기 | 여러 학교용 공개 서비스 |
| | 결제 |

### 1.4 용어

| 용어 | 뜻 |
|---|---|
| 대회 | 골든벨 한 판 |
| 문제 은행 | 선생님들이 출제한 문제 전체 |
| 편성 | 대회에 쓸 문제를 고르고 순서를 정하는 일 |
| 라운드 | 예선, 본선, 패자부활, 결승 같은 문제 묶음 |
| 예비 문제 | 문제에 오류가 있을 때 대신 내는 문제 |
| 생존자 / 탈락자 | 아직 남은 학생 / 탈락한 학생 |
| 진행자 화면 | 사회자 PC의 조작 화면. 정답이 보이므로 **프로젝터에 띄우면 안 됨** |
| 무대 화면 | 프로젝터로 띄우는 화면 |
| 학생 화면 | 학생이 자기 기기에서 답을 내는 화면 |

### 3.2 대회 당일 흐름

```
① 진행자 로그인 → 진행자 화면 열기
② 무대 화면을 프로젝터에 띄움 → 참가 QR·코드 표시
③ 학생 접속 → 학번·이름 입력 → 대기실
④ 진행자 [대회 시작]
⑤ 문제 반복
   문제 공개 → (사회자가 문제 읽기) → 타이머 시작 → 답 제출
   → 마감 → 정답 공개 → 탈락 확정 → 다음 문제
⑥ 조건이 되면 패자부활전
⑦ 생존자 1명 → 골든벨 문제 도전
   문제 소진 → 공동 우승 또는 서든데스
⑧ 우승 발표 → 결과 저장
```

## 5. 기능 상세

### 5.1 계정 (A)
- 관리자가 선생님 계정을 일괄 생성 (이름, 아이디, 담당 과목) → 초기 비밀번호 발급 → 첫 로그인 때 변경 강제
- 비밀번호를 잊으면 관리자가 초기화
- 쓰지 않는 계정은 비활성화. 그 선생님이 낸 문제는 유지
- 로그인 유지: 서버 세션 쿠키 (`httpOnly`, `Secure`, `SameSite=Lax`)
- 로그인 5회 실패 시 해당 아이디 5분 잠금

### 5.2 문제 출제 (Q)

#### 공통 항목

| 항목 | 필수 | 설명 |
|---|:-:|---|
| 유형 | ✅ | OX / 객관식 / 단답 / 초성 / 숫자 / 순서 |
| 과목 | ✅ | 목록에서 선택 |
| 학년 | | 대상 학년 |
| 난이도 | ✅ | 쉬움 / 보통 / 어려움 |
| 문제 내용 | ✅ | 최대 300자 (무대 화면에서 읽기 좋게) |
| 첨부 | | 이미지 1장 (P0), 소리·영상 (P2) |
| 정답 | ✅ | 유형별로 다름 (5.3 참고) |
| 해설 | | 정답 공개 때 표시, 최대 200자 |
| 제한시간 | | 비우면 유형별 기본값 |
| 출제자 메모 | | 관리자만 봄 (예: "교과서 54쪽") |

#### 문제 상태

```
작성중 ──제출──▶ 제출됨 ──승인──▶ 승인됨 ──(대회 편성 잠금)──▶ 사용됨
  ▲               │
  └──반려(사유)───┘
```

- 제출한 문제는 선생님이 회수해서 다시 작성중으로 돌릴 수 있음
- 승인된 문제를 선생님이 고치면 다시 제출됨 상태가 되어 재검수
- 편성을 잠그면 문제 내용을 대회 쪽에 복사(스냅샷)해 둠. 이후 원본이 바뀌어도 대회 문제는 그대로

#### 문제 목록 (선생님)
- 필터: 상태, 유형, 과목
- 상태별 개수: `작성중 3 · 제출 5 · 승인 12 · 반려 1`
- 반려된 문제에는 반려 사유 표시

#### 미리보기
- 학생 폰 화면과 무대 화면 두 가지로 확인
- 글자가 넘치면 경고

#### 엑셀 일괄 업로드
1. 템플릿 다운로드 (부록 A)
2. 작성 후 업로드
3. 행별 검사 결과 미리보기 (예: `7행: 객관식 정답 번호(5)가 보기 개수(4)보다 큼`)
4. 오류 없는 행만 작성중 상태로 저장
- 이미지는 업로드한 뒤 웹에서 문제별로 첨부

### 5.3 문제 유형 상세

#### OX (P0)

| 항목 | 내용 |
|---|---|
| 학생 화면 | 큰 O / X 버튼 2개. O는 파란 원, X는 빨간 X로 색과 모양을 함께 써서 구분 |
| 출제 입력 | 정답 O 또는 X |
| 판정 | 일치하면 정답 |
| 정답 공개 | 정답 크게 표시, O/X 선택 비율 막대 |
| 기본 시간 | 10초 |

#### 객관식 (P0)

| 항목 | 내용 |
|---|---|
| 학생 화면 | 보기 버튼을 세로로 배치(번호 + 내용), 1개 선택 |
| 출제 입력 | 보기 2–5개 (기본 4개, ⚠️ 작년 기준 확인), 정답 번호 1개 이상 |
| 판정 | 고른 번호가 정답 번호 중 하나면 정답. 정답을 2개 지정하면 둘 다 인정하며, 출제 오류를 정정할 때도 이 방식 사용 |
| 보기 섞기 | 선택 기능, 기본 끔. 켜면 학생마다 보기 순서가 다르고, 무대 화면은 번호 없이 보기를 표시하며, 정답은 번호가 아니라 보기 내용으로 공개 |
| 정답 공개 | 정답 보기 강조, 보기별 선택 인원 막대 |
| 기본 시간 | 15초 |

#### 단답형 (P0)

| 항목 | 내용 |
|---|---|

### 5.6 순서 편성 (관리자)
- **화면 구성:** 왼쪽에 승인된 문제 은행(필터: 과목·유형·난이도·출제자), 오른쪽에 대회 문제 목록
- **조작:** 끌어다 놓아 추가하고 순서를 바꿈
- **라운드 구분선:** 예선 / 본선 / 패자부활 / 결승(골든벨 문제) / 예비
- **문제별 제한시간 덮어쓰기**
- **자동 정렬 (P2):** 난이도 오름차순, 같은 과목이 연달아 나오지 않게
- **요약:** 총 문항 수, 유형별·과목별 개수, 예상 소요 시간 (`문항 수 × (제한시간 + 진행 여유 40초)`)
- **경고:**
  - 결승 문제가 없음
  - 예비 문제가 0개
  - 패자부활을 쓰는데 패자부활 문제가 없음
- **잠금:** 잠그면 스냅샷이 만들어지고 편성을 고칠 수 없음. 해제는 관리자만, 대회 시작 전까지만 가능
- **인쇄용 문제지 (C-06):** `/admin/contests/:id/print` 페이지를 브라우저에서 PDF로 저장

### 5.7 참가 (학생)
- **접속:** 무대 화면 QR, 또는 주소 + 6자리 코드
- **입력:** 학번, 이름 (⚠️ 학번 형식 확인, 예: `20315` = 2학년 3반 15번)
- **명단을 쓰는 경우:** 학번·이름이 명단과 일치해야 참가 ("명단에 없습니다. 다시 확인해주세요")
- **대기실:** "○○○님, 곧 시작합니다" + 현재 참가 인원
- **참가 마감:** 1번 문제 시작 후 새 참가 불가 (재접속은 가능)
- **같은 학번으로 중복 접속:**
  - 같은 기기 (토큰 있음): 자동 복귀
  - 다른 기기: 진행자 화면에 "기기 변경 요청" 표시 → 승인하면 새 기기로 옮기고 이전 기기 연결 끊음
- **탈락 후:** 관전 모드. 문제·타이머·정답은 계속 보이고 답 입력만 막힘

### 5.8 대회 진행 (G)

#### 진행 상태

| 상태 | 코드 | 무대 화면 | 학생 화면 | 다음 단계 |
|---|---|---|---|---|
| 대기실 | `LOBBY` | QR·코드·참가 인원 | 대기 | 시작 → `READING` |
| 문제 공개 | `READING` | 문제 표시, 타이머 대기 | 문제 보임, 입력 잠김 | 타이머 시작 → `ANSWERING` |
| 답변 중 | `ANSWERING` | 문제 + 타이머 + 제출 수 | 입력 가능 | 0초 또는 즉시 마감 → `CLOSED` |
| 마감 | `CLOSED` | "마감!" | 입력 잠김, 내 답 표시 | 정답 공개 → `REVEALED` |
| 정답 공개 | `REVEALED` | 정답·해설·통계 | 정답/오답 표시 | 탈락 확정 → `CONFIRMED` |
| 결과 | `CONFIRMED` | 이번 탈락 수·생존 수 | 생존/탈락 표시 | 다음 문제 / 패자부활 / 종료 |
| 일시정지 | `PAUSED` | "잠시 멈춤" | "잠시 멈춤" | 재개 → 이전 상태 |
| 종료 | `FINISHED` | 우승자 발표 | 최종 결과 | — |

- 학생 화면은 `REVEALED` 때 "정답! / 오답"만 보여주고, "탈락" 문구는 `CONFIRMED` 뒤에 표시. 진행자가 정답을 고칠 수 있기 때문

```
LOBBY → READING → ANSWERING → CLOSED → REVEALED → CONFIRMED ─┬→ READING (다음 문제)
                   (+10초)              (정답 수정,           ├→ READING (패자부활 문제)
                                         수동 판정)           └→ FINISHED
                                            ▲                │
                                            └── 되돌리기 ────┘

언제든: 일시정지(PAUSED) / 문제 무효 → 예비 문제로 READING
```

#### 진행자 조작

| 버튼 | 누를 수 있는 상태 | 동작 | 확인창 |
|---|---|---|:-:|
| 대회 시작 | `LOBBY` | 1번 문제 공개 | ✅ |
| 타이머 시작 | `READING` | 답변 시작 | |
| +10초 | `ANSWERING` | 마감 시각 10초 연장 (여러 번 가능) | |
| 즉시 마감 | `ANSWERING` | 바로 마감 | ✅ |
| 정답 공개 | `CLOSED` | 정답·통계 공개 | |
| 정답 수정 | `REVEALED` | 다른 답도 인정하고 재채점 | ✅ |
| 유사 답안 인정 | `REVEALED` | 단답 유사 답안을 정답 처리하고 재채점 | |
| 탈락 확정 | `REVEALED` | 오답·미제출 생존자 탈락 | ✅ |
| 되돌리기 | `CONFIRMED` | 직전 탈락 확정 취소 → `REVEALED` | ✅ |
| 다음 문제 | `CONFIRMED` | 다음 문제 공개 (진행자 화면에 다음 문제 미리보기) | |
| 패자부활 시작 | `CONFIRMED` | 패자부활 문제 공개 | ✅ |
| 문제 무효 | `READING`~`CONFIRMED` | 이번 문제의 제출·탈락 전부 취소 → 예비 문제 공개 | ✅ |
| 일시정지 / 재개 | 언제든 | 타이머 멈춤 / 이어서 | |
| 개별 부활·탈락 | `ANSWERING` 외 | 학생 1명 상태 변경 (사유 입력, 기록) | ✅ |
| 대회 종료 | 언제든 | 종료 | ✅ |

- 버튼은 지금 상태에서 누를 수 있는 것만 활성화
- 모든 조작은 진행 기록(`host_logs`)에 저장

#### 탈락 규칙
- 탈락 확정 시 이번 문제 대상자(생존자) 중 오답이거나 미제출인 학생이 탈락
- 전원이 탈락하게 되면 진행자 화면에 경고: `전원 탈락합니다. [그대로 확정] [이 문제 무효]`

#### 패자부활전
- **대상:** 그 시점의 탈락자 전원. 생존자는 "패자부활전 진행 중" 대기 화면
- **방식:** 편성에 넣은 패자부활 문제(1개 이상)를 맞힌 탈락자가 부활
- **최대 인원을 정한 경우:** 정답자 중 빨리 제출한 순서로 부활
- **시점:** 편성에서 위치를 정해 두는 것이 기본이고, 진행자가 직접 시작할 수도 있음
- **횟수:** 기본 1회

#### 종료 규칙
- 생존자가 1명이 되면 진행자 화면에 "골든벨 문제로 이동" 제안. 남은 일반 문제는 건너뜀
- 골든벨 문제를 맞히면 "골든벨 달성!" 연출. 틀려도 최종 우승자 (⚠️ 확인)
- 문제가 다 떨어졌는데 생존자가 여러 명이면 공동 우승(기본) 또는 예비 문제로 서든데스

#### 순위
- 늦게 탈락할수록 높은 순위. 같은 문제에서 탈락하면 같은 순위
- 부활한 학생은 마지막으로 탈락한 시점 기준

### 5.9 타이머 (G-02)

#### 화면별 표시

| 화면 | 표시 |
|---|---|
| 무대 화면 | 강당 뒤에서도 보이는 큰 숫자 + 줄어드는 막대. 초록 → 노랑 → 마지막 5초 빨강 깜빡임. 0초에 "마감!" |
| 학생 화면 | 상단에 남은 초 + 줄어드는 막대. 마지막 5초 빨강, 안드로이드는 진동. 0초에 버튼 잠금, "마감되었습니다" |
| 진행자 화면 | 남은 시간 + 제출 현황 (`7초 · 182/240명 제출`), `+10초` `즉시 마감` `일시정지` 버튼 |

#### 시간 설정
- 유형별 기본값:

| OX | 객관식 | 단답·초성 | 숫자 | 순서 | 골든벨 문제 |
|:-:|:-:|:-:|:-:|:-:|:-:|
| 10초 | 15초 | 30초 | 20초 | 30초 | 40초 |

- 적용 순서: 편성에서 덮어쓴 값 > 문제에 설정한 값 > 유형 기본값

#### 시작 방식 (대회 설정)
- **진행자가 시작 (기본):** 문제가 뜨면 사회자가 읽고 나서 [타이머 시작]
- **자동:** 문제가 뜨고 읽기 시간(기본 5초)이 지나면 자동 시작. 읽기 시간 동안 "읽는 중" 표시, 입력 잠김

#### 동작 규칙
- 0초가 되면 자동 마감 (기본)
- 마감 판정은 **서버 시각으로만** 함
- **유예 0.5초:** 화면은 0초에 잠그지만, 마감 직전에 보낸 답이 네트워크 때문에 늦게 도착할 수 있으므로 서버는 마감 후 0.5초까지 도착한 제출을 인정
- **+10초:** 여러 번 누를 수 있고 모든 화면에 바로 반영
- **일시정지:** 남은 시간을 저장해 두었다가 재개하면 이어서 진행
- **즉시 마감:** 남은 시간과 상관없이 마감

#### 시간 동기화 방식
- 서버는 "10초 남음"이 아니라 **마감 시각**(`endsAt`, 서버 시계 기준 절대 시각)을 보냄
- 각 기기는 접속할 때 서버와 시계 차이(`offset`)를 잼
  1. `time:ping`을 5번 보냄
  2. 왕복 시간이 가장 짧았던 응답을 고름
  3. `offset = 서버시각 − (보낸 시각 + 받은 시각) / 2`
  4. 30초마다 다시 잼
- 남은 시간 = `endsAt − (기기 시각 + offset)`
  - 숫자는 초 단위 올림으로 표시
  - 막대는 `requestAnimationFrame`으로 부드럽게 줄임
- 이렇게 하면 기기 시계가 틀려도, 중간에 접속해도, 앱을 내렸다가 돌아와도 모든 화면에 같은 숫자가 뜸

#### 효과음
- 무대 화면에서만 재생: 타이머 시작음, 마지막 5초 째깍, 마감 부저, 정답 공개음, 우승 팡파레
- 직접 만들거나 사용이 허가된 무료 효과음만 씀 (출처 기록). 방송 프로그램 음악·효과음은 쓰지 않음
- 브라우저는 사용자가 한 번 클릭해야 소리를 재생할 수 있으므로, 무대 화면을 열 때 [소리 켜기] 버튼을 둠

#### 예외 상황

| 상황 | 처리 |
|---|---|
| 기기 시계가 틀림 | offset으로 보정 |
| 답변 중에 재접속 | 남은 시간을 이어서 표시하고 이미 낸 답 복원 |
| 화면이 꺼졌다 켜짐, 탭 전환 | 돌아오면 `endsAt` 기준으로 즉시 다시 계산 |
| 서버 재시작 | 일시정지 상태로 복구 → 진행자가 재개 |
| 진동 | 안드로이드만 지원 (iOS 사파리는 지원 안 함) |

### 5.10 채점 (G-03, G-07, G-08)
- 채점은 서버에서만 함. 제출 즉시 채점해서 저장하되, 공개 전까지는 아무에게도 보내지 않음

#### 단답 정규화 순서
1. 유니코드 정규화 (NFC)
2. 앞뒤 공백 제거, 중간 공백 모두 제거
3. 영문은 소문자로
4. 전각 문자를 반각으로 (`Ａ→A`, `１→1`)
5. 문장부호 제거: `. , ! ? ' " · ( ) - ~`

- 정답 목록도 같은 방법으로 정규화한 뒤 비교
- 예: `" 세종 대왕! "` → `"세종대왕"` → 정답

#### 유사 답안
- 한두 글자만 다르거나(예: `세종대앙`) 정답을 포함하는 답은 일단 오답 처리
- 진행자 화면의 "유사 답안" 목록에 같은 답끼리 묶어 인원수와 함께 표시
- [인정]을 누르면 그 답을 낸 학생 전원을 정답 처리. 탈락 확정 전에만 가능

#### 재채점
- 정답 수정이나 유사 답안 인정 시 그 문제 전체를 다시 채점하고 기록을 남김

### 5.11 무대 화면 연출 (S)

| 상태 | 표시 |
|---|---|
| 대기실 | 대회 제목, QR, 주소·코드, 참가 인원 (실시간으로 늘어남) |
| 문제 공개 | 라운드·번호 (`본선 15/30`), 유형 배지, 문제, 이미지, 보기, 초성 힌트 |
| 답변 중 | 위 내용 + 타이머 + 제출 수 |
| 마감 | "마감!" 전환 |
| 정답 공개 | 정답 강조, 해설, 유형별 통계 |
| 결과 | `이번 문제 탈락 23명 · 생존 117명` |
| 패자부활 | "패자부활전" 안내, 대상 인원 |
| 우승 | 우승자 이름 (학번 제외), 축하 연출 |

- 탈락자 이름은 무대에 띄우지 않고 인원수만 표시
- 생존자가 설정 인원(기본 10명) 이하가 되면 생존자 이름 표시
- 1920×1080 기준, 문제 글자는 최소 48px
- 학교 로고는 원본 모양 그대로 쓰고(18장), 색·글꼴·연출은 디자인 가이드(17장)를 따름
- 방송 프로그램의 로고·디자인·음악은 쓰지 않음

### 5.12 결과와 통계 (R)
- **최종 순위**
- **학생별 기록:** 문제마다 낸 답, 정답 여부, 제출 시각
- **문제별 통계:** 정답률, 평균 응답 시간, 보기별 선택 수, 많이 나온 오답
- **진행 기록:** 언제 누가 어떤 조작을 했는지 (`host_logs`)
- **CSV 내보내기:** 순위, 학생별 기록, 문제별 통계. 엑셀에서 한글이 깨지지 않게 UTF-8 BOM을 붙여 저장
- **진행 중 생존자 명단 CSV:** 서버 장애에 대비해 진행 중에도 다운로드 가능
- **선생님:** 본인 문제의 통계만 볼 수 있음

## 8. 실시간 통신 설계

### 8.1 연결 구조
- Socket.IO, 네임스페이스 `/game`
- 기본은 WebSocket. 학교망에서 막히면 HTTP 롱폴링으로 자동 전환
- 방(room) 구분:

| 방 | 들어가는 쪽 |
|---|---|
| `c:{id}:host` | 진행자 |
| `c:{id}:stage` | 무대 화면 |
| `c:{id}:players` | 학생 전체 |
| `p:{participantId}` | 학생 개인 |

### 8.2 인증
- **진행자:** 로그인 세션 쿠키 + 해당 대회 진행 권한 확인
- **무대:** `stage_key` 확인
- **학생:** 참가할 때 받은 토큰. 서버에는 해시만 저장하고, 기기에는 `localStorage`의 `gb:{contestId}:token`에 보관

### 8.3 설계 원칙: 스냅샷 방식
- 상태가 바뀔 때마다 받는 쪽에 맞춘 **전체 상태(스냅샷)**를 보냄. 변경분만 보내지 않음
  - 이벤트를 놓쳐도 다음 스냅샷으로 맞춰짐
  - 재접속도 같은 코드로 처리
- 받는 쪽별 내용:
  - 학생: 내 상태와 내 답 포함, 정답은 공개 후에만
  - 무대: 통계 포함
  - 진행자: 정답, 제출 명단, 알림까지 전부
- 자주 바뀌는 제출 수는 `progress`로 따로 보내고, 초당 최대 2번으로 묶음

### 8.4 이벤트 명세

**기기 → 서버**

| 이벤트 | 보내는 쪽 | 내용 | 응답 |
|---|---|---|---|
| `time:ping` | 모두 | `{ t0 }` | `{ serverNow }` |
| `player:join` | 학생 | `{ code, studentNo, name, token? }` | `{ ok, participantId, token, state }` 또는 `{ ok:false, error }` |
| `player:submit` | 학생 | `{ cqId, answer }` | `{ ok, receivedAt }` 또는 `{ ok:false, error }` |
| `player:visibility` | 학생 | `{ hidden }` | 없음 |
| `host:attach` | 진행자 | `{ contestId }` | `{ ok, state }` |
| `host:command` | 진행자 | `{ commandId, type, args }` | `{ ok }` 또는 `{ ok:false, error }` |
| `stage:attach` | 무대 | `{ contestId, stageKey }` | `{ ok, state }` |

- `player:join` 오류: `NOT_FOUND`, `NOT_IN_ROSTER`, `JOIN_CLOSED`, `DEVICE_CHANGE_PENDING`
- `player:submit` 오류: `CLOSED`, `LOCKED`(수정 불허), `NOT_ALIVE`, `INVALID`
- `host:command`의 `type`: `START`, `START_TIMER`, `EXTEND`, `CLOSE`, `REVEAL`, `SET_ANSWER`, `ACCEPT_SIMILAR`, `CONFIRM`, `UNDO`, `NEXT`, `START_REVIVAL`, `VOID`, `PAUSE`, `RESUME`, `REVIVE`, `ELIMINATE`, `APPROVE_DEVICE`, `REJECT_DEVICE`, `FINISH`
- `commandId`: 버튼을 두 번 눌러도 한 번만 실행되게 하는 고유값
- `host:command` 오류: `INVALID_STATE`, `FORBIDDEN`, `DUPLICATE`

**서버 → 기기**

| 이벤트 | 받는 쪽 | 내용 |
|---|---|---|
| `state` | 각자 | 받는 쪽에 맞춘 전체 상태 |
| `progress` | 진행자·무대 | `{ submitted, alive, connected }` |
| `timer` | 전체 | `{ endsAt, paused, remainingMs }` (연장·일시정지 때) |
| `alert` | 진행자 | 기기 변경 요청, 유사 답안, 연결 끊김, 전원 탈락 경고 |
| `kicked` | 학생 개인 | 다른 기기로 옮겨져 연결 종료 |

### 8.5 학생 스냅샷 예시

```json

  "round": "MAIN",
  "index": 15,
  "total": 30,
  "question": {
    "cqId": "cq_15",

    "mediaUrl": null,
```

### 8.6 접속·재접속 흐름

```
[처음 참가]
학생 → join(code, 학번, 이름)
서버: 명단 확인 → 참가자 생성 → 토큰 발급 → state 응답
학생: 토큰을 localStorage에 저장

[재접속: 새로고침, 와이파이 끊김]
학생 → join(code, 학번, 이름, token)
서버: 토큰 일치 → 같은 참가자로 복귀 → 현재 state(현재 문제, 마감 시각, 내 답) 응답

[다른 기기로 같은 학번]
학생(새 기기) → join(토큰 없음)
서버 → 진행자에게 alert(기기 변경 요청)
진행자 승인 → 이전 기기에 kicked → 새 기기에 토큰 발급
```

### 8.7 서버 장애 복구
- 상태가 바뀔 때마다 `contest_runs`에 저장, 제출은 받는 즉시 `submissions`에 저장
- 서버가 다시 켜지면 진행 중이던 대회를 DB에서 불러옴
  - 답변 중이었다면 남은 시간을 계산해 일시정지 상태로 복구
- 기기들은 자동으로 재접속하고 스냅샷을 다시 받음 → 진행자가 [재개]

## 10. 보안·공정성·개인정보

### 10.1 정답 보호
- 정답은 공개 버튼을 누르기 전까지 학생 기기로 **절대 보내지 않음**. 개발자도구로 볼 수 없게 하기 위해서
- 대회 시작 전에는 문제 조회 API를 선생님·관리자만 쓸 수 있음 (문제 유출 방지)
- 진행자 화면은 프로젝터에 띄우지 않음 (운영 매뉴얼에 명시)

### 10.2 계정과 권한
- 비밀번호는 argon2 또는 bcrypt로 해시해서 저장
- 모든 API에서 역할과 소유자를 확인 (선생님은 남의 문제에 접근 불가)
- 진행자 명령은 세션과 대회 진행 권한을 매번 확인

### 10.3 입력 검증
- 모든 입력을 zod 스키마로 검증 (REST와 소켓 모두)
- 문제 내용은 텍스트로만 표시하고 HTML로 해석하지 않음 (XSS 방지)
- 업로드는 형식·크기를 검사하고 이미지는 다시 인코딩해서 저장

### 10.4 접속 제한
- 학교 와이파이에서는 학생 전원이 같은 공인 IP로 보일 수 있음
  - IP 기준 제한은 넉넉하게 잡음
  - 대신 대회 코드와 명단으로 막음
- 로그인은 아이디별 5회 실패 시 5분 잠금

### 10.5 부정행위 대책
- 서버 시각으로만 마감 판정
- 한 학번은 한 기기만 (기기 변경은 진행자 승인)
- 객관식 보기 섞기 (선택)
- 검색은 웹으로 완전히 막을 수 없음
  - 제한시간을 짧게 함
  - 현장 감독
  - 화면 이탈 표시 (P2, 참고용)

### 10.6 개인정보
- 수집 항목은 최소로: 학번, 이름, 반
- 목적: 대회 진행과 결과 기록
- 보관: 대회 후 30일 뒤 삭제 또는 익명화 (⚠️ 학교 개인정보 담당 선생님께 확인)
- 접근: 관리자·진행자만
- 무대 화면에는 탈락자 이름을 띄우지 않음
- 모든 접속은 HTTPS

### 12.4 게임 엔진 설계 원칙
- 엔진은 순수 함수처럼 만듦: `(현재 상태, 명령) → (새 상태, 보낼 내용)`. 테스트하기 쉬움
- 명령은 현재 상태에서 허용될 때만 실행하고, 아니면 거절하면서 이유를 돌려줌
- `commandId`로 중복 실행을 막음 (버튼 두 번 클릭 대비)
- 상태가 바뀔 때마다 DB에 저장 (장애 복구)
- 채점 함수는 서버에만 둠. 정규화 함수만 공용 패키지에 둠 (미리보기용)

### 12.5 배포와 환경
- 환경 변수: `DATABASE_URL`, `SESSION_SECRET`, `UPLOAD_DIR`(또는 저장소 키), `PUBLIC_URL`
- 개발용과 운영용 DB를 나눔
- 1주차부터 배포해 두고 계속 올림 (마지막에 몰아서 배포하지 않기)
- 대회 전날 DB 수동 백업
- 비용: 무료 플랜은 접속이 없으면 서버가 잠들거나 DB 사용 기간에 제한이 있는 경우가 많음. 대회 전후 한두 달은 최소 유료 플랜을 권장 (⚠️ 업체별 요금, 학교 지원 여부 확인)

## 14. 테스트 계획

### 14.1 자동 테스트 (단위·통합)

- **규칙**
  - 미제출 = 오답
  - 전원 탈락 경고

## 17. 디자인 가이드

### 17.1 디자인 방향

| 후보 | 느낌 | 장점 | 단점 |
|---|---|---|---|
| A. 무대 쇼형 | 어두운 남색 바탕 + 금색 조명 | 정답 공개·우승 연출이 가장 멋짐 | 밝은 강당에서는 프로젝터의 검정이 회색으로 떠서 대비가 약함. 폰·관리 화면에는 무거움 |
| **B. 플레이풀 (추천)** | 밝은 바탕 + 굵은 검정 테두리 + 원색 | 강당에서 잘 보임, 보기 구분이 쉬움, 가벼워서 폰·학교 와이파이에 유리, 만들기 쉬움 | 고급스러운 느낌은 덜함 |
| C. 미니멀 | 흰 바탕 + 큰 글씨 + 포인트 색 하나 | 깔끔하고 세련됨 | 행사 분위기·게임감이 약함, 보기 구분이 약함 |

- **추천:** B를 기본으로 하고, 무대 화면의 정답 공개와 우승 발표 순간에만 A의 어두운 조명 연출을 섞음 (⚠️ 선택 필요)

| 화면 | 적용 |
|---|---|
| 학생 화면 | B. 큰 버튼, 밝은 바탕 |
| 무대 화면 | B 기본, 정답 공개·우승 순간에 A 연출 |
| 진행자 화면 | B를 차분하게 (그림자·색 줄이고 정보 위주) |
| 선생님·관리자 화면 | B를 차분하게 (표·입력 양식 위주) |

### 17.2 색

| 이름 | 값 | 쓰임 |
|---|---|---|
| school-blue | `#3D9AFF` | 학교 로고 색. 포인트, 보기 ②, O 표시 |
| school-blue-deep | `#1F6FE0` | 흰 글씨를 올리는 버튼·배지 |
| gold | `#F5C542` | 골든벨 포인트, 타이머 막대, 우승 연출, 보기 ③ |
| ink | `#141414` | 글씨, 테두리, 그림자 |
| paper | `#FFF6E0` | 기본 바탕 (무대·학생 화면) |
| white | `#FFFFFF` | 카드, 입력칸 |
| red | `#FF8A8A` | 보기 ①, X 표시 |
| green | `#86D993` | 보기 ④, 정답 표시 |
| stage-night | `#0B1030` | 정답 공개·우승 연출 배경 |

- **대비 규칙:** `#3D9AFF` 위의 흰 글씨는 대비가 부족함 (약 2.9:1). 이 색 위에는 ink 글씨(약 6.4:1)를 쓰고, 흰 글씨가 필요하면 `#1F6FE0`(약 4.8:1)을 씀
- **색만으로 구분하지 않기:** 보기는 번호와 색을 함께, O/X는 모양(원, X)과 색을 함께 씀

| FLUX.2 edit | — | 대안 |

- **다시 시작하는 순서:**
  1. `/mcp` → fal → Authenticate (브라우저 로그인, 크레딧 충전)

  3. 방향 선택 후 추가 생성
